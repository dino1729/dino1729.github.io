Memory Palace is a local knowledge workspace for finding, checking, and revisiting saved material. Its central interaction is small: ask a question, read the matching passages, and open the source without losing the thread.

The project began as a fork of McKay Wrigley’s paul-graham-gpt. My version adds a shared local index, exact source passages, linked-note exploration, a source library, saved work, and optional AI synthesis. The upstream starting point and my adaptations are distinct parts of the story.

Start with finding, then explore

The baseline audit found that a large discovery section could push search results far down the page. Retrieval and graph exploration also drew from different collections, so a concept visible in one view was not necessarily available in the other.

The current workspace puts evidence immediately after the question and moves exploration into its own view. Both use the same source index. That gives a selected concept a concrete meaning: it scopes the question to that note instead of merely suggesting some prompt text.

A simpler retrieval decision, with a test behind it

The previous ranker relied on substring matches. The current implementation uses BM25, English stemming, title weighting, minimum term coverage, and per-source limits. Common words contribute less; a multi-word query needs more than one incidental match.

I kept retrieval local and separate from synthesis. Embeddings and reranking remain possible extensions, but the recorded comparison gives a reason to start with the smaller system. It also makes an important limitation clear: this is lexical search. A paraphrase with no shared vocabulary can still miss the right note.

The full app’s recorded evaluation from 23 October 2026 compares both rankers on the same 1,018-source, 1,599-passage corpus. It uses 40 answerable questions and 10 questions expected to have no evidence:

Check Previous ranker Current ranker
Expected source in the top five 37 of 40 40 of 40
Correctly returns no evidence 4 of 10 10 of 10

These are results from a small, hand-authored regression set, not a general claim about search quality. They do not evaluate every generated answer. The evaluation script and its boundaries are documented in the app repository; the public sample uses a separate collection of eight original example notes.

Make checking the answer cheap

Each result retains its source identity and exact passage. Opening a citation reveals the evidence, and the source view provides the surrounding text. A reader can distinguish an original note from an imported summary or preview.

AI synthesis is off by default in the full app. When enabled, it sends the question and selected evidence to a configured model gateway. The app returns local excerpts if the model is unavailable, and it does not call a model when retrieval finds no evidence. A citation makes a claim checkable; it does not establish that the claim is true.

The implementation and regression tests cover Unicode queries, source edits, exclusions, request cancellation, and interrupted answers. Those details matter because a convincing interface should also be understandable when the answer is missing or a dependency fails.

Try the narrow version

The public sample demonstrates search, exact excerpts, and opening a result in context. Search for hysteresis to find the idea in both comparators and branch prediction, or try cafe to find café. Try a topic outside the collection to see the empty state.

The sample is a browser-only adaptation of the full app’s BM25 approach, without its English stemmer, CJK segmentation, index management, or AI features. It contains original educational examples rather than personal vault material. The source library remains readable with JavaScript disabled.
