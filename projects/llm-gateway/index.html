Home LLM Gateway

One address for many models

The home laboratory · 1 min read · 19 Oct 2026

Once several applications use language models, changing a provider becomes a coordination problem. Each app has a client, a credential, a model name, and its own assumptions about the service behind them.

My home gateway puts a LiteLLM endpoint between those applications and their models. A Raspberry Pi can host the routing layer because it forwards requests; the model computation happens elsewhere. Bots, research tools, and other clients connect through the same interface.

The useful boundary is between what an application asks for and where the request goes. Changing a model mapping in one place is easier to reason about than editing several unrelated projects. Provider credentials can stay with the gateway instead of being copied into each client.

Centralization has a cost. A broken gateway can affect every application that depends on it. It also cannot make models interchangeable: context limits, tool behavior, speed, and output quality still differ. An unchanged API shape does not guarantee unchanged behavior.

The gateway earns its place by making those dependencies explicit. It gives the model layer a location I can inspect and maintain, while leaving each application responsible for whether a particular model is suitable for its task.
